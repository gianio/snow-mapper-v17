> **Why inline-gzip was deferred:** the browser `DecompressionStream` API is
> async, but the app's raster arrays are decoded synchronously at boot and the
> whole UI is built from global functions that inline `onclick` handlers depend
> on. Making decode async would force wrapping the boot in an async closure and
> break those global handlers — too risky for a stability-focused launch, and
> not browser-testable in CI. Mitigations already in place: GitHub Pages
> (Fastly) gzips the HTML response in transit, and the service worker makes
> repeat/installed loads instant. Revisit with the full data-blob split.

## Manual steps (only you can do these)

1. **Supabase → SQL Editor:** run `web/migration-latest.sql` (safe to re-run).
   Then **Database → Backups:** enable daily backups.
2. **Supabase → Authentication → Email Templates → "Confirm signup":** make sure
   the body includes the 6-digit code token `{{ .Token }}` (the app uses
   `verifyOtp`, not the magic link).
3. **GitHub → Settings → Pages → Source: "GitHub Actions".** Without this, Pages
   serves the Jekyll placeholder instead of the app.
4. **Powder regression cache (optional):** run `python tools/eval_powder.py`
   once on a machine with internet (it caches Open-Meteo archive data under
   `tools/cache/`), then commit `tools/cache/`. CI then runs the offline powder
   regression as a real gate; until committed the CI step is a no-op.
5. **Sentry (optional but recommended):** create a project, copy the browser DSN,
   and paste it into the `SENTRY_DSN` constant in the generated app
   (search `SENTRY_DSN` in `pipeline/interactive_export.py`). Leaving it empty
   disables Sentry cleanly.
