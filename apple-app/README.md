# Snow Model — iOS App (Capacitor wrapper)

This folder turns the existing **Snow Model web app** into a native iOS app
that can ship to **TestFlight → the App Store**, without touching the web app.

- **The web app is unchanged.** It is still generated by
  `../pipeline/interactive_export.py` and deployed to GitHub Pages exactly as
  before. This project just runs that same build and bundles the output as the
  app's web assets, then adds iOS-native integrations.
- **Approach:** [Capacitor](https://capacitorjs.com) — an Apple-approved native
  shell around a WKWebView. The whole feature set (map, powder engine, feed,
  reporting, Supabase auth, offline data) is reused as-is.

> **What you can do here vs. on a Mac.** Everything in this folder (config,
> build scripts, icons, docs) is ready. The final steps — generating the native
> `ios/` project, signing, and uploading — **require a Mac with Xcode and an
> Apple Developer account** ($99/yr). They cannot be done on Linux/CI without a
> macOS runner. Those steps are spelled out below.

---

## App identity (change once)

Defaults: **app name `Snow Model`**, **bundle ID `ch.snowmodel.app`**.
To rebrand, edit the two constants at the top of `capacitor.config.ts`. The
bundle ID must be a reverse-domain string **you** control and must match the
Bundle Identifier you register in App Store Connect.

## Prerequisites (on your Mac)

1. **Xcode** (latest, from the Mac App Store) + Command Line Tools.
2. **Node 18+** and **npm** (`node -v`).
3. **CocoaPods**: `sudo gem install cocoapods` (or `brew install cocoapods`).
4. **Python 3** + the repo's pipeline deps: from the repo root,
   `pip install -r requirements.txt` (needed to build the web assets).
5. **Apple Developer Program** membership, and an **App Store Connect** app
   record with the bundle ID above.

## One-time setup

```bash
cd apple-app
npm install                      # Capacitor + plugins

npm run build:web                # generates ./www from the Python pipeline
npm run resources                # (re)generate resources/icon.png + splash.png

npx cap add ios                  # creates the native ios/ Xcode project
npx capacitor-assets generate --ios   # app icon + splash in every size
npx cap sync ios                 # copies www/ + plugins into ios/
```

Then apply the iOS-specific config **once** (see `ios-config/`):

- **Info.plist** — open `ios/App/App/Info.plist` and add the keys from
  `ios-config/Info.plist.additions.xml` (camera / photo / location purpose
  strings are **mandatory** or Apple rejects the build).
- **Privacy manifest** — add `ios-config/PrivacyInfo.xcprivacy` to the Xcode
  `App` target (right-click *App* → *Add Files to "App"…*).

## Everyday build & run

```bash
cd apple-app
npm run ios          # build:web → cap sync → open Xcode
```

or step by step:

```bash
npm run build:web    # rebuild web assets (e.g. after editing the web app)
npm run sync         # cap sync ios
npm run open         # open Xcode, then ▶ to run on a simulator or device
```

Environment knobs for `build:web`:

| Var | Effect |
|---|---|
| `SNOW_BUILD_ARGS` | args to `run_interactive.py` (default `--split --res 3000`) |
| `SNOW_OFFLINE=1` | use synthetic weather (no network); good for a quick smoke test |
| `PYTHON` | python executable (default `python3`) |

## Data delivery

Currently the app **bundles the forecast data** inside the binary (via the
`--split` build copied into `www/`), so it works fully offline on first launch.

- **To refresh the forecast:** re-run `npm run build:web && npm run sync` and
  ship a new build. (Fine for a test app / periodic releases.)
- **To fetch data remotely instead** (smaller binary, always-fresh): host the
  `data/` folder + `latest.json` (GitHub Pages already serves them) and change
  the boot loader to fetch from that absolute URL. The split build already
  fetches `data/latest.json` relative — point it at the hosted URL. This is the
  recommended optimisation once the basic app is approved.

## Native integrations included

The web app auto-detects Capacitor (`window.Capacitor`) and upgrades transparently
— in a plain browser these are no-ops:

| Feature | Web app | Inside the iOS app |
|---|---|---|
| Haptics | `navigator.vibrate` (ignored by iOS Safari) | **`@capacitor/haptics`** (real Taptic Engine) |
| Status bar | theme-color meta | **`@capacitor/status-bar`** overlay + dark style |
| Splash | in-app `#intro` loader | **`@capacitor/splash-screen`** hidden after boot |
| Location | `navigator.geolocation` | works in WKWebView with the Info.plist string |
| Camera / photo | `<input type=file capture>` | native picker with the Info.plist strings |
| Share | Web Share where available | **`@capacitor/share`** (`nativeShare()` helper) |
| Keyboard | — | **`@capacitor/keyboard`** resize handling |

`@capacitor/app` and `@capacitor/geolocation` are installed and ready to wire
deeper (deep links, background permission prompts) if a reviewer asks for more.

## App Store compliance checklist

Already handled **in the web app** (reused by the iOS app):

- ✅ **Account + data deletion** in-app (profile → *Konto & Daten löschen*) —
  Guideline 5.1.1(v).
- ✅ **Data export** (profile → *Meine Daten exportieren (JSON)*).
- ✅ **Safety / liability + privacy consent gate** on first run (avalanche
  disclaimer, DSG note) — doubles as your EULA/consent.
- ✅ **UGC moderation**: per-post flag + auto-hide after 3 flags, per-user rate
  limit — Guideline 1.2. Commit to acting on reports within 24 h.
- ✅ **First-party auth** (email OTP). Because there is **no** third-party/social
  login, **Sign in with Apple is _not_ required** (Guideline 4.8).

Still **your** manual steps (documented, can't be done from code):

- ⬜ **Privacy Policy URL** + Support URL — host a page and put the links in App
  Store Connect (and consider linking it from the consent gate).
- ⬜ **App Privacy labels** in App Store Connect — mirror `PrivacyInfo.xcprivacy`
  (email, precise location, photos, user content; none for tracking).
- ⬜ **Info.plist purpose strings** + **PrivacyInfo.xcprivacy** added (above).
- ⬜ **Demo account** for App Review (a test email login they can use).
- ⬜ Confirm Supabase **account-deletion Edge Function** removes the `auth.users`
  row (the client deletes the profile + cascades content; deleting the login
  row itself needs the service role — see `web/migration-latest.sql` notes).

## Sign → TestFlight → App Store (on your Mac)

1. **Signing:** open `ios/App/App.xcworkspace` in Xcode → *Signing & Capabilities*
   → select your Team; let Xcode manage the provisioning profile. Set the
   Bundle Identifier to match `capacitor.config.ts`.
2. **Version/build:** bump *Version* (e.g. 1.0.0) and *Build* (e.g. 1).
3. **Archive:** *Product → Destination → Any iOS Device*, then *Product → Archive*.
4. **Upload:** in the Organizer, *Distribute App → App Store Connect → Upload*.
   (Or automate with [fastlane](https://fastlane.tools): `gym` + `pilot`.)
5. **TestFlight:** in App Store Connect, add the build to **TestFlight**.
   *Internal testers* (≤100, no review) install immediately; *external testers*
   (≤10,000) need a light Beta App Review. **This is your "test app ready for the
   App Store."**
6. **App Store release:** fill metadata (category *Weather*, keywords,
   description, screenshots at 6.7"/6.5"), privacy labels, age rating, then
   submit for full App Review.

### No Mac?

Use a cloud macOS build service — **Codemagic**, **Ionic Appflow**, or **EAS
Build** — which run `npx cap sync ios`, sign, and upload from a hosted Mac.
Point them at this `apple-app/` folder.

## Troubleshooting

- **`build:web` fails** → run `pip install -r requirements.txt` in the repo
  root, or `SNOW_OFFLINE=1 npm run build:web` to skip the live data fetch.
- **White screen in the app** → `www/` is empty; run `npm run build:web` then
  `npm run sync`.
- **Camera/location does nothing** → the Info.plist purpose strings are missing
  (see `ios-config/Info.plist.additions.xml`).
- **Pods errors** → `cd ios/App && pod install --repo-update`.
- **CDN/tiles blocked** → ensure the device has network; map tiles + Supabase
  load over https (App Transport Security allows https by default).
