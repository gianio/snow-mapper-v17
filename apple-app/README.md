# Snowmapper — iOS + Android app (one Capacitor project)

This folder turns the existing **Snow Model web app** into native apps for
**iOS (TestFlight → App Store)** and **Android (Google Play)**, without
touching the web app. Despite the folder name, it is the project for both
platforms. It keeps its name so existing links, workflows and the Xcode
download keep working.

- **The web app is unchanged.** It is still generated by
  `../pipeline/interactive_export.py` and deployed to GitHub Pages exactly as
  before. This project just runs that same build and bundles the output as the
  app's web assets, then adds native integrations.
- **Approach:** [Capacitor](https://capacitorjs.com) 8 — a native shell around
  the system WebView (WKWebView on iOS, Chromium WebView on Android). The whole
  feature set (map, powder engine, feed, reporting, Supabase auth, offline
  data) is reused as-is.

> **iOS needs a Mac (or the macOS CI runner); Android does not.** The Android
> app builds on Linux, Windows or a Mac with Android Studio, or entirely in CI
> (`.github/workflows/android-build.yml`).

---

## How iOS and Android stay in sync

There is nothing to sync by hand, because there is only one of everything:

| Shared — edit once, both apps get it | Per platform — generated, never edited by hand |
|---|---|
| The web app (`pipeline/interactive_export.py` → `www/`) | `ios/` and `android/` (not in git; recreated by `cap add` on every CI build) |
| `capacitor.config.ts` — app id `ch.snowmapper.app`, name, plugin settings | `scripts/apply-ios-config.py` / `scripts/apply-android-config.py` — permissions, purpose strings, orientation |
| `package.json` — **one** Capacitor version and **one** set of plugins | `scripts/ci-signing.py` (iOS) / signing env vars (Android) |
| `resources/` — icon + splash for both stores | `ios-config/` (Info.plist strings, privacy manifest) |
| **Version** — use the same `version` input (e.g. `1.0.0`) in both workflows | Build number: iOS build number / Android versionCode (each workflow's run number) |

Rules that keep it that way:

1. **Feature work happens in the web app.** It reaches both apps on the next
   build. The web code talks to native features only through `_capPlugin(...)`,
   which is a no-op in a browser, so one code path serves web, iOS and Android.
   Check `_CAP.getPlatform()` (`'ios'`/`'android'`) only where the platforms really differ
   (e.g. the Android back button).
2. **A plugin is added to `package.json` once**, then `npx cap sync` installs
   it into both native projects.
3. **Release both from the same commit** with the same version: run
   `ios-testflight.yml` and `android-build.yml` on that commit.
4. **Upgrade Capacitor for both at once** (all `@capacitor/*` to the same major).
   Google Play requires target API 36 for new apps and updates from
   31 Aug 2026, which is why this project is on Capacitor 8.

## App identity (change once)

Defaults: **app name `Snowmapper`**, **app id `ch.snowmapper.app`** (iOS bundle ID and Android applicationId).
To rebrand, edit the two constants at the top of `capacitor.config.ts`. The
bundle ID must be a reverse-domain string **you** control and must match the
Bundle Identifier you register in App Store Connect.

## Prerequisites — iOS (on your Mac)

1. **Xcode** (latest, from the Mac App Store) + Command Line Tools.
2. **Node 22+** and **npm** (`node -v`) — Capacitor 8 needs it.
3. **CocoaPods**: `sudo gem install cocoapods` (or `brew install cocoapods`).
4. **Python 3** + the repo's pipeline deps: from the repo root,
   `pip install -r requirements.txt` (needed to build the web assets).
5. **Apple Developer Program** membership, and an **App Store Connect** app
   record with the bundle ID above.

## One-time setup (iOS)

```bash
cd apple-app
npm install                      # Capacitor + plugins

npm run build:web                # generates ./www from the Python pipeline
npm run resources                # (re)generate resources/icon.png + splash.png

npx cap add ios --packagemanager CocoaPods   # creates the native ios/ Xcode project
npx capacitor-assets generate --ios   # app icon + splash in every size
npx cap sync ios                 # copies www/ + plugins into ios/
```

Then apply the iOS-specific config **once** (see `ios-config/`):

- **Info.plist** — open `ios/App/App/Info.plist` and add the keys from
  `ios-config/Info.plist.additions.xml` (camera / photo / location purpose
  strings are **mandatory** or Apple rejects the build).
- **Privacy manifest** — add `ios-config/PrivacyInfo.xcprivacy` to the Xcode
  `App` target (right-click *App* → *Add Files to "App"…*).

## Everyday build & run (iOS)

```bash
cd apple-app
npm run ios          # build:web → cap sync → open Xcode
```

or step by step:

```bash
npm run build:web    # rebuild web assets (e.g. after editing the web app)
npm run sync:ios     # cap sync ios
npm run open:ios     # open Xcode, then ▶ to run on a simulator or device
```

Environment knobs for `build:web`:

| Var | Effect |
|---|---|
| `SNOW_BUILD_ARGS` | args to `run_interactive.py` (default `--split --res 3000`) |
| `SNOW_OFFLINE=1` | use synthetic weather (no network); good for a quick smoke test |
| `PYTHON` | python executable (default `python3`) |

## Data delivery

Currently the app **bundles the forecast data** inside the binary (via the
`--split` build copied into `www/`), so it works fully offline on first launch.

- **To refresh the forecast:** re-run `npm run build:web && npm run sync` and
  ship a new build. (Fine for a test app / periodic releases.)
- **To fetch data remotely instead** (smaller binary, always-fresh): host the
  `data/` folder + `latest.json` (GitHub Pages already serves them) and change
  the boot loader to fetch from that absolute URL. The split build already
  fetches `data/latest.json` relative — point it at the hosted URL. This is the
  recommended optimisation once the basic app is approved.

## Native integrations included

The web app auto-detects Capacitor (`window.Capacitor`) and upgrades transparently
— in a plain browser these are no-ops:

| Feature | Web app | Inside the iOS app |
|---|---|---|
| Haptics | `navigator.vibrate` (ignored by iOS Safari) | **`@capacitor/haptics`** (real Taptic Engine) |
| Status bar | theme-color meta | **`@capacitor/status-bar`** overlay + dark style |
| Splash | in-app `#intro` loader | **`@capacitor/splash-screen`** hidden after boot |
| Location | `navigator.geolocation` | works in WKWebView with the Info.plist string |
| Camera / photo | `<input type=file capture>` | native picker with the Info.plist strings |
| Share | Web Share where available | **`@capacitor/share`** (`nativeShare()` helper) |
| Keyboard | — | **`@capacitor/keyboard`** resize handling |

`@capacitor/app` and `@capacitor/geolocation` are installed and ready to wire
deeper (deep links, background permission prompts) if a reviewer asks for more.

## App Store compliance checklist

Already handled **in the web app** (reused by the iOS app):

- ✅ **Account + data deletion** in-app (profile → *Konto & Daten löschen*) —
  Guideline 5.1.1(v).
- ✅ **Data export** (profile → *Meine Daten exportieren (JSON)*).
- ✅ **Safety / liability + privacy consent gate** on first run (avalanche
  disclaimer, DSG note) — doubles as your EULA/consent.
- ✅ **UGC moderation**: per-post flag + auto-hide after 3 flags, per-user rate
  limit — Guideline 1.2. Commit to acting on reports within 24 h.
- ✅ **First-party auth** (email OTP). Because there is **no** third-party/social
  login, **Sign in with Apple is _not_ required** (Guideline 4.8).

Still **your** manual steps (documented, can't be done from code):

- ⬜ **Privacy Policy URL** + Support URL — host a page and put the links in App
  Store Connect (and consider linking it from the consent gate).
- ⬜ **App Privacy labels** in App Store Connect — mirror `PrivacyInfo.xcprivacy`
  (email, precise location, photos, user content; none for tracking).
- ⬜ **Info.plist purpose strings** + **PrivacyInfo.xcprivacy** added (above).
- ⬜ **Demo account** for App Review (a test email login they can use).
- ⬜ Confirm Supabase **account-deletion Edge Function** removes the `auth.users`
  row (the client deletes the profile + cascades content; deleting the login
  row itself needs the service role — see `supabase/migrations/20260901000000_privacy_moderation_ratings.sql` notes).

## Sign → TestFlight → App Store (on your Mac)

1. **Signing:** open `ios/App/App.xcworkspace` in Xcode → *Signing & Capabilities*
   → select your Team; let Xcode manage the provisioning profile. Set the
   Bundle Identifier to match `capacitor.config.ts`.
2. **Version/build:** bump *Version* (e.g. 1.0.0) and *Build* (e.g. 1).
3. **Archive:** *Product → Destination → Any iOS Device*, then *Product → Archive*.
4. **Upload:** in the Organizer, *Distribute App → App Store Connect → Upload*.
   (Or automate with [fastlane](https://fastlane.tools): `gym` + `pilot`.)
5. **TestFlight:** in App Store Connect, add the build to **TestFlight**.
   *Internal testers* (≤100, no review) install immediately; *external testers*
   (≤10,000) need a light Beta App Review. **This is your "test app ready for the
   App Store."**
6. **App Store release:** fill metadata (category *Weather*, keywords,
   description, screenshots at 6.7"/6.5"), privacy labels, age rating, then
   submit for full App Review.

### No Mac?

Use a cloud macOS build service — **Codemagic**, **Ionic Appflow**, or **EAS
Build** — which run `npx cap sync ios`, sign, and upload from a hosted Mac.
Point them at this `apple-app/` folder.

## Android — build, run, ship

### Without installing anything: CI

Every pull request that touches the app runs `.github/workflows/android-build.yml`:
it builds the web app, generates `android/`, builds a **debug APK** and
smoke-tests it on an Android 16 emulator. Download **`snowmapper-debug-apk`**
from the run's *Artifacts*, copy it to any Android phone and open it (allow
"install unknown apps" once). That is the fastest way to try the app.

### On your computer (Linux, Windows or Mac)

Prerequisites: **Android Studio** (it brings the SDK and a JDK 21), Node 22+,
Python 3 + `pip install -r requirements.txt`.

```bash
cd apple-app
npm install
npm run build:web                 # same web build as iOS
npx cap add android               # creates android/ (once; not in git)
npx capacitor-assets generate --android
npx cap sync android
npm run config:android            # permissions, portrait, version, signing hook
npm run open:android              # Android Studio → ▶ on an emulator or phone
```

Everyday: `npm run android` (build:web → sync → open Android Studio), or
`npm run apk` for a debug APK at `android/app/build/outputs/apk/debug/`.
If you delete `android/`, rerun the setup block above. Nothing in it is
hand-edited.

### What differs from iOS (already handled)

| Topic | Android |
|---|---|
| Back button / back gesture | Closes the open sheet/modal (replays the existing Escape handling); with nothing open it moves the app to the background |
| Edge-to-edge (forced from API 35) | `SystemBars.insetsHandling: 'native'` makes the web app's `env(safe-area-inset-*)` correct on new WebViews and pads the view on old ones |
| Tour recording with screen off | Foreground service + notification ("Aktivität wird aufgezeichnet"), `android.useLegacyBridge: true` so updates do not stop after 5 min |
| Camera / photos | System camera app + Android photo picker — no CAMERA or media permission needed |
| Face ID | Fingerprint / face unlock via the same biometric plugin |
| "Add to Home Screen" prompt | Hidden inside the native app (also fixed for iOS) |
| Bundled forecast | `.gz` only (a `capacitor:copy:after` hook). Android's asset packer rejects `x.json` next to `x.json.gz`, and every Android WebView reads the `.gz` |

### Google Play: one-time steps (only you can do these)

| # | Step | Time |
|---|---|---|
| 1 | **Play Console developer account** (25 USD once) + identity verification | days – 2 weeks |
| 2 | Create the app **`ch.snowmapper.app`** in Play Console. The package name can never change | minutes |
| 3 | **Upload key**: `keytool -genkey -v -keystore upload.jks -keyalg RSA -keysize 2048 -validity 10000 -alias upload`. **Back it up**; it never goes in git (`*.jks` is ignored) | minutes |
| 4 | Repo secrets: `ANDROID_KEYSTORE_BASE64` (`base64 -w0 upload.jks`), `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS`, `ANDROID_KEY_PASSWORD` | minutes |
| 5 | First release by hand: run the workflow with `upload: true` (without `PLAY_SERVICE_ACCOUNT_JSON` the upload step is skipped), download **`snowmapper-release-aab`**, upload it in Play Console → *Testing → Internal testing*. Opt in to **Play App Signing** | an hour |
| 6 | Service account for automatic uploads: Google Cloud → service account → JSON key; invite it in Play Console → *Users and permissions* with release rights; secret `PLAY_SERVICE_ACCOUNT_JSON` | an hour |
| 7 | Store listing, **Data safety** form (email, precise location, photos, user content; mirrors the iOS privacy labels), content rating, privacy policy URL, **account-deletion web link** | an afternoon |
| 8 | **Foreground-service declaration** for `FOREGROUND_SERVICE_LOCATION` (tour recording): short video of starting a recording | review: days |
| 9 | **New personal accounts: closed test with ≥ 12 testers for 14 days in a row**, then apply for production access | **14 days + up to 7 days review** |
| 10 | Production release with **managed publishing**, so you press "publish" yourself (like Manual release on iOS) | review: hours – days |

After step 6, every release is: *Actions → Android build → Run workflow →
upload: true, version 1.x.y*. The build goes to internal testing; promote it in
Play Console.

## Testing — both platforms

| Level | What | iOS | Android |
|---|---|---|---|
| 1. Automatic, every PR | Python/model tests + web JS check | `validate.yml` | `validate.yml` |
| 2. Automatic, every PR | Native build + launch | — (manual, macOS runner minutes) | `android-build.yml`: APK + emulator smoke test (install, launch, back button, no crash) + screenshot |
| 3. You, on a device | Click through the app | Xcode download / TestFlight internal | debug APK from the PR, or Play *Internal testing* (≤ 100 testers, no review) |
| 4. Testers | Real use | TestFlight external | Play *Closed testing* (needed anyway: 12 testers × 14 days) |
| 5. Google's robots | Crawls the app on real devices | — | Play *Pre-launch report* (automatic for every upload) |

**Device checklist** (do it on one iPhone and one Android phone, ideally a
cheap one, since WebView speed varies a lot on Android):

- [ ] First launch **offline** (airplane mode): map + bundled forecast appear
- [ ] Location: permission prompt, blue dot, "where am I"
- [ ] Report with photo: camera **and** gallery
- [ ] Sign up / log in with the e-mail code; log out; delete account
- [ ] Record a tour, lock the screen for 10 min, unlock: track continues
      (Android: notification visible while recording)
- [ ] Android only: back closes sheets one by one, then leaves the app; the
      status/navigation bars do not cover buttons (top bar, tab bar)
- [ ] Biometric lock on/off
- [ ] Share a post → system share sheet
- [ ] Dark mode, large system font

A local run of the emulator smoke test with a phone plugged in (USB debugging
on): `bash scripts/android-smoke.sh android/app/build/outputs/apk/debug/app-debug.apk`.

## Troubleshooting

- **`build:web` fails** → run `pip install -r requirements.txt` in the repo
  root, or `SNOW_OFFLINE=1 npm run build:web` to skip the live data fetch.
- **White screen in the app** → `www/` is empty; run `npm run build:web` then
  `npm run sync`.
- **Camera/location does nothing** → the Info.plist purpose strings are missing
  (see `ios-config/Info.plist.additions.xml`).
- **Pods errors** → `cd ios/App && pod install --repo-update`.
- **CDN/tiles blocked** → ensure the device has network; map tiles + Supabase
  load over https (App Transport Security allows https by default).
- **Android: `SDK location not found`** → open `android/` once in Android
  Studio, or set `ANDROID_HOME`.
- **Android: `Unsupported class file major version`** → Gradle needs JDK 21
  (Android Studio's bundled JDK, or `JAVA_HOME`).
- **Android: "App not installed"** over an older APK → uninstall first; a debug
  APK and a Play build are signed with different keys.
